# SISTA BUSSEN — agent contract

Survivor-like mobile web game (Vite + TypeScript + Canvas 2D, PWA). Read `README.md`, `DESIGN.md`,
`INTEGRATION.md` and `ROADMAP.md` before changing anything. The vault note
`04 - Code/Project Notes/dsf-mobilspel.md` holds status and handoff.

## Tickets

**GitHub Issues in `VasthavM/sista-bussen` are the tickets.** Acceptance criteria in the issue body and its
comments are the eval. `specs/tickets/board.md` mirrors issue numbers with status, mode and dependencies.
`ROADMAP.md` holds the reasoning behind the order. Execution lives in the issues.

## Commands

```bash
npm install
npm run build          # tsc --noEmit + vite build
npm test               # vitest unit tests
npx playwright test    # e2e (boots the built game)
H=<host> node tools/live-check.mjs   # smoke-check a deployment
```

## Hard rules

- `src/sim/` is frozen. It's a deterministic, knife-edge balanced sim. Change it only with a failing test as the
  reason, and re-run the 240-second win check in `tests/run.test.ts`.
- `src/meta/` and `src/monetize/` change only test-first. Save changes need a forward migration and a migration test.
- Every price, cap, cooldown and gate constant lives in `src/monetize/catalog.ts`. Never in UI code.
- One HUD (DOM). The stick is the only in-canvas UI.
- `screenshots/` is committed visual evidence, regenerated by e2e.
- Keep the Dockerfile deploy path. Coolify's static build pack ships an empty site.

## Branches

- Integration branch per wave: `totto/<feature>` off `main`. Workers branch off the integration branch.
- Nobody pushes, deploys or merges to `main` unless Max asked for it in that session.
